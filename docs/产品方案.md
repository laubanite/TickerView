## 一、产品定位

**上班族个人交易的"执行助手":昨晚计划 × 盘中状态 × AI 逐条核对 → 一眼决策 → 手机下单。**

- **不是行情软件**:图表能力不追求与同花顺/东财对标,行情页只是"核对引擎的显示器"
- **不是自动交易**:所有下单由人执行,系统只出判断、提示与建议
- **核心价值**:把"作战地图(计划)+ 实时行情"核对成一眼能懂的状态,替代"上班偷偷盯盘 + 大脑心算"

## 二、目标用户与场景

| 场景         | 痛点                     | 产品解法                                 |
| ------------ | ------------------------ | ---------------------------------------- |
| 上班盯盘     | 注意力稀缺,没空看盘      | 悬浮面板只给结论,细节走快照              |
| 决策依赖计划 | 盘中临时起意、被情绪接管 | 所有输出对照作战地图的"若…则…"规则     |
| 手机交易     | 下单在手机,看盘在电脑    | 快照/提醒一键推送手机,面板定位后手机执行 |
| 复盘         | 收盘后懒得回填           | 盘后按钮自动生成收盘对账 + 复盘五问      |

## 三、核心设计原则

1. **面板只显示结论,不显示需要换算的数据**——不展示量比数字,只展示"放量/缩量"结论;不展示"距触发 2.9%",只展示"接近买点/等待·缺条件"
2. **差异输出**——有动作的重点写,无变化的一行带过或置暗;快照只输出有变化标的
3. **分层各管一件事**——速查表管基准、剧本管变化、快照管实时、提醒管兜底
4. **计划层不被机器污染**——AI 生成的内容必须人工确认后才写入作战地图
5. **手动下单,自动提醒**——系统绝不自动交易,但主动推送触发状态

├─────────────────────────────────────────────────┤
│ ② 核对引擎  解析器 + 实时行情 + 逐条核对(产品命门)     │

├─────────────────────────────────────────────────┤
│ ③ 展示层  悬浮面板(状态灯) / 行情页(三 tab) / AI 快照  │

**信息流**:作战地图(周级,独立)→ 剧本+卡片(日级,进 tab)→ 快照/对账(日内,生成物)→ 手机(执行端)

### 4.1 作战地图 → 解析器接口定义(规则模型)

**解析器把作战地图(自然语言+表格的 .md)解析成机器可核对的结构化 RuleModel。这是核对引擎的输入契约,也是用户自定义作战地图(§5.7)的写入目标——同一个模型,解析器读、生成器写。**

```
RuleModel(单文件/JSON,含 schema_version)
├─ meta        : {文档日期, 版本, 数据源, 适用原则}      ← 文档头
├─ global      : 组合层
│  ├─ 大盘门控    : {条件, 命中动作}                      ← §一 环境结论
│  │               例: 大盘收盘<MA60 → 所有"接近买点"降级"等待·缺条件"
│  └─ 弹药预算    : {总额, 分配表[标的→预算/占比]}          ← §三 加仓预算分配
├─ instruments : 标的层(每只)
│  ├─ meta      : {code, name, type: 波段仓|解套仓, 结构: 上升|震荡|下降}
│  ├─ position  : {持有股数, 成本, 现价, 市值, 浮亏%, 解套需涨}  ← §二 持仓表(只展示,不做决策)
│  ├─ levels    : 关键价位(每项必须带溯源注释,红线溯源原则)
│  │              {买区上/下沿, 突破点, 减仓红线, 生命线, 止损价, 目标位1/2/3}
│  ├─ rules     : 触发规则表(动作 × 条件)
│  │              {动作: 加仓①/加仓②/目标位减仓/红线减仓/新仓止损/清仓红线,
│  │               条件: 逻辑表达式 = 价格 × 量能(量比/量能等级) × 指标(KDJ/MACD/均线) × 大盘门控,
│  │               动作: 加X股(预算Y%)/减X股/清仓/换仓}
│  └─ alerts    : {基本面预警, 消息面催化🔴🟢⚪}             ← 非数值,只入快照不做核对
└─ daily       : 日级层
   ├─ playbook  : 剧本修正表 {品种, 隔夜影响, 今日动作}    ← 盘前生成,当日覆盖基准
   └─ journal   : 盯盘记录(每日追加的 剧本/对账/复盘)
```

**章节→字段映射(解析器的表头契约)**:

| 作战地图章节 | RuleModel 字段 | 解析方式 |
|---|---|---|
| §一 大盘环境 | global.大盘门控 | 规则抽取(收盘/均线/KDJ + 环境结论) |
| §二 持仓一览表 | instruments[].position | 表格解析(列名固定) |
| §三 逐只分析·关键位地图 | instruments[].levels | 数值提取 + 溯源注释保留 |
| §三 逐只分析·操作建议表 | instruments[].rules | **核心:每行"动作/触发条件/具体操作"→ 一条触发规则** |
| §三 基本面预警/消息面 | instruments[].alerts | 分类(预警/催化/风险) |
| 剧本修正表 | daily.playbook | 表格解析,当日生效 |
| 每日盯盘记录 | daily.journal | 追加写,不覆盖历史 |

**设计约束**:① levels 的每个数字必须带溯源(锚定具体日期低点/高点);② rules 的条件必须是可计算表达式,不可计算(如"情绪面")的进 alerts 不进 rules;③ 解析失败或有歧义 → 进"待人工确认"队列,绝不猜测。**这条约束同时保护解析器和 §5.7 生成器。**

## 五、功能规格

### 5.1 悬浮面板(桌面右下角置顶小窗)

只给结论,细节走快照按钮。每行:**现价 | 涨跌 | 放量/缩量 | 结论词**。

```
[大盘破位·防守]                    10:03        ← 前置条件灯,最上
化工   0.876 +0.34% 放量  接近买点
半导体 0.772 -2.89% 放量  等待·缺条件
通信   1.062 -3.54% 放量  接近卖点
光伏   0.864 -2.92% 放量  平静(置暗)
黄金   9.086 -0.91% 平量  平静(置暗)
电池   0.884 -1.78% 放量  平静(置暗)
电网   1.700 -2.80% 平量  平静(置暗)
[盘中快照]   [展开行情页]
```

**结论词 5 档(引擎判定,颜色区分)**:

| 结论词       | 颜色         | 判定逻辑                                   |
| ------------ | ------------ | ------------------------------------------ |
| 平静         | 灰(整行置暗) | 远离所有触发点                             |
| 接近买点     | 黄           | 距买区/突破点近,且条件满足                 |
| 接近卖点     | 橙           | 贴近减仓红线/生命线                        |
| 等待·缺条件 | 紫           | 接近买点但被禁(大盘破位/未企稳/信号不满足) |
| 买点触发     | 红闪         | 条件全满足,该动手(人决定)                  |

**量能标签**:放量(暖色)/ 缩量(冷色)/ 平量(中性),阈值复用 monitor:量比 >1.5 放量、<0.8 缩量。量能不分好坏,只配合结论解读。

**大盘灯联动**:大盘破位时,引擎自动把所有"接近买点"降级为"等待·缺条件"(作战地图硬规则)。

**底部按钮仅 2 个**:盘中快照 / 展开行情页。隐藏细节走快照,不做趋势图/迷你图。

### 5.2 行情页(点悬浮面板展开)

```
┌──────────────────────────────────────────┐
│ 顶栏: Logo | [盘前][盘中*][盘后] | 🗺 作战地图 │
├──────────────────────────────────────────┤
│ 指数区: 上证 / 科创综指 / 深成指 / 创业板(可配置) │ ← 现价+涨跌,破位高亮
├──────────────────────────────────────────┤
│ 自选股区: 每行 = 名称/现价/涨跌/量比/状态/结论   │ ← 点击切换图表标的
│ 图表区: 分时 | 日K | 30分K                   │ ← 三 tab 共用
│   主图 K线/分时 + 速查卡价位自动叠线            │
│   副图: 成交量 + MACD + KDJ                 │
├──────────────────────────────────────────┤
│ 辅助面板(随顶部 tab 切换):                     │
│   盘前 = 隔夜消息 + 剧本修正表 + 纪律 + 持仓卡    │
│   盘中 = 实时核对表 + [🤖 生成盘中快照]          │
│   盘后 = 收盘对账 + 复盘五问 + [📋 生成对账]     │
└──────────────────────────────────────────┘
```

要点:

- **图表区三个 tab 共用**,盘前/盘后 tab 下图表照常显示(数据为昨收/收盘);tab 只切换辅助面板
- **速查卡价位自动叠线**:买区高亮 + 前高/减仓线/生命线虚线,越出坐标范围的自动隐藏
- 指数区只做现价/涨跌/分时,不堆全套指标

### 5.3 三个 tab 的内容

| Tab            | 辅助面板内容                                                                                     | 生成动作                                                   |
| -------------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| **盘前** | ① 隔夜消息(🔴利空/🟢利好/⚪中性 分类)② 剧本修正表(品种/隔夜影响/今日动作)③ 今日纪律 ④ 持仓卡 | [生成今日剧本] → 草稿确认后追加写入作战地图"每日盯盘记录" |
| **盘中** | 实时核对表(剧本×速查表×实时行情 → 未到/已触发/缺条件)+ 快照输出区                             | [🤖 生成盘中快照] → 差异输出 + 可推手机                   |
| **盘后** | 收盘对账 + 复盘五问 + 收盘待办                                                                   | [📋 生成收盘对账] → 追加写入当日盯盘记录,替换"待填"       |

### 5.4 AI 快照(盘中核心输出)

- **差异输出**:有动作的 1-3 条重点写,其余一行折叠
- **结论先行**:大盘状态 → 标的现状表 → 判断 → 接下来只看一件事 → 纪律重申
- **规则驱动**:引擎用速查表+剧本+实时行情算事实,LLM 只做解读与措辞;快照不脱离用户自定规则
- **流式生成**:边生成边显示(借鉴 helm-agents),不干等
- **一键推送手机**:复用 push webhook

### 5.5 作战地图(独立入口,不进 tab)

- 悬浮面板/行情页顶栏 → [🗺 作战地图] → 独立页只读渲染全文,按章节折叠(§一~§八)
- 提供"在编辑器中打开"按钮,维持现有编辑工作流
- tab 里只展示它的**衍生物**(持仓卡/速查卡/剧本/对账),绝不嵌套全文
- 解析结果缓存,每日只重读新增盯盘记录段落

### 5.6 自选股管理(搜索/添加/删除)

自选股 = **用户主动添加的资产**,不是系统预置。系统只负责渲染,管理入口必须完整。

- **入口**:行情页顶栏 `＋` 按钮 / 悬浮面板右键菜单 → 搜索弹窗
- **搜索**:按代码精确添加(v0.1.0 MVP,复用腾讯 `qt.gtimg.cn` 实时接口 + `fetch_name` 自动取名);按名称模糊搜索 v0.2+(需接入搜索接口,与数据源抽象一并评估)
- **增删排序**:添加/删除/手动排序;与 CLI `alphaprism pool add/remove` 打通,UI 操作同步写 `watchlist.yaml`
- **两类标的,两种状态灯语义**:
  | 类型 | 来源 | 状态灯 |
  |---|---|---|
  | 计划内标的 | 作战地图速查表有价位 | 完整结论词(接近/等待/触发/卖点) |
  | **临时观察股** | 用户新添加、尚无计划 | 只显示行情 + 放/缩量,**结论词固定"无计划"**(灰),绝不臆造买卖结论;悬浮面板中置暗显示 |
- **引导闭环——生成计划草稿(临时观察股 → 计划内标的的唯一通道)**:
  - 入口:自选股列表该行"无计划"标签旁的 `生成草稿` 链接(真实产品为按钮)
  - 内容:AI 按「低吸决策 + 交易计划」两个方法论,结合该股技术面/基本面,生成草稿——关键位 / 回踩买点 / 突破买点 / 止损 / 减仓红线
  - 流程:草稿 → **盘前确认流**(人工确认/修改)→ 写入作战地图速查表 → 升级为计划内标的:速查卡出现该股价位、图表开始叠线、悬浮面板给完整结论词
  - **原则红线**:所有买卖结论必须来自"被确认过的计划",草稿未经确认绝不出结论

### 5.7 用户自定义作战地图(提示词 → 作战地图)

**需求**:用户不认可现有打法、或要微调(止损放宽/加仓节奏不同/只信某类信号),可以引入自己的策略。但手写一份作战地图(数百行、红线溯源、表格格式)门槛太高——**用户只输入提示词,系统自动:理解意图 → 检索已有 skill 方法论 → 提取规则 → 生成作战地图草稿 → 校验 → 人工确认 → 写入。**

**生成流程(与 §5.6"生成计划草稿"同一条管线,扩展为整份地图)**:

```
用户提示词("我想要:回调不追高,只做突破确认加仓,单笔止损5%,单笔目标10%,仓位每笔10%")
   ↓ ① 意图理解(LLM)      → 结构化策略描述 {入场偏好, 止损, 目标, 仓位, 红线, 放弃}
   ↓ ② skill 检索          → 从技能库(本地 skills/)语义检索最匹配的方法论
   ↓                        (例: 匹配 trade_plan_builder_skill / dip_buy_decision_skill)
   ↓ ③ 规则提取            → 按 RuleModel schema(§4.1)填成规则草稿
   ↓ ④ 数值补全            → 关键位/止损/目标 从实时行情+技术指标算出(腾讯/Wind),禁止凭空编
   ↓ ⑤ 校验门              → schema 校验 + 数值可溯源校验 + 与用户提示词一致性校验(§eval)
   ↓ ⑥ 人工确认            → 盘前确认流(草稿 → 编辑 → 保存)
   ↓ ⑦ 写入                → 生成标准格式作战地图.md(速查表/持仓表/操作建议表/剧本)
```

**难度评估(诚实版)**:

| 环节 | 难度 | 说明 |
|---|---|---|
| ① 意图理解 | 低 | LLM 把自然语言映射到固定策略维度,有 30 秒结论式的模板可循 |
| ② skill 检索 | **低** | skill 均为带 YAML 头(name/description/keywords)的 .md,做语义检索即可(嵌入或关键词),不需要 skill 运行时调用 |
| ③ 规则提取 | **中高** | 真正的工作量:把意图映射到 RuleModel 的 rules 条件表达式。需 schema 设计 + few-shot + 校验器兜底 |
| ④ 数值补全 | 中 | 关键位从行情/指标算出(复用 monitor 指标引擎),与用户策略合并。**防幻觉的核心环节** |
| ⑤ 校验门 | 中 | 复用 §eval 层:结构校验 + 溯源校验 + 一致性校验 |
| ⑥⑦ 确认/写入 | 低 | 模板化生成 + 现有盘前确认流 |

**结论:可行,和现有架构完全兼容,且依赖的都是本项目已有能力(LLM 解读层 + 指标引擎 + 解析器 schema)。总工作量约 3-5 天,分两阶段:**

- **v0.2:规则模型 + 校验器落地**(§4.1 RuleModel + 校验门)——解析器本来就需要的,先做,让"读"和"写"共用同一契约
- **v0.3:提示词 → 草稿生成**(意图理解 + skill 检索 + 数值补全 + 生成)——把"手工写地图"降为"提示词+人工确认"

**三条硬约束(保护安全边界)**:
1. **数字必溯源**:所有生成的关键位/止损/目标必须标注数据来源(日期低点/技术指标值),无法溯源的一律标"待人工确认",绝不编造——红线溯源原则从解析器延伸至生成器
2. **生成 ≠ 生效**:任何自动生成内容必须走盘前确认流,人工确认后才写入作战地图(§三 原则4"计划层不被机器污染")
3. **skill 是方法论文本,不是执行器**:检索到 skill 只借用其规则模板,不执行任何 skill 里的动作;skill 方法论与用户提示词冲突时,以用户提示词为准并提示差异

## 七、版本策略(一个仓库,两种模式)

`settings.yaml` 配置 `mode: personal / public`,代码 95% 共用:

| 差异点    | personal(个人版)       | public(开源版)                                       |
| --------- | ---------------------- | ---------------------------------------------------- |
| 作战地图  | 真实持仓/成本/资金     | 脱敏示例模板                                         |
| 快照措辞  | 可含"执行加仓②1500股" | 条件句纪律:"若放量站稳 0.90,则补涨确认",结论止于状态 |
| 持仓/推送 | 全开                   | 不解析持仓字段、不内置推送                           |
| 免责      | 弱提示                 | 固定免责声明 + 快照头部免责                          |

**法律依据**:国内《证券法》《证券、期货投资咨询管理暂行办法》要求面向公众提供证券投资咨询需牌照;开源版定位为"用户自定规则的核对工具",只做行情分析+规则核对,不生成投资建议,是安全路径。

## 八、数据源策略与 TickFlow 评估

**现状(v0.1.0)**:核心数据全部用腾讯接口实测打通且免费(见 §六),另有同花顺 fuyao + 新浪/Wind。**不引入 TickFlow 依赖**,没有一处非用它不可。

**TickFlow(tickflow-org)评估结论:占位不做主源,三个真实增益点留到后续版本**:

| 增益点 | 价值 | 版本 |
|---|---|---|
| **备用数据源** | 上班场景最怕断数据;腾讯/同花顺为网页接口,有改版/限流/封禁风险;TickFlow 为商业 API,可作故障切换源 | v0.1.0 架构预留,切换实现 v0.3+ |
| **竞价确认** | 9:15-9:25 集合竞价 → 9:25 出"开盘快照",提前确认高开/低开,衔接"盘前剧本 → 开盘落地" | v0.2+ |
| **生态参考(最值)** | `shy3130/tickflow-stock-panel`(TSP,3140★,FastAPI+React+DuckDB+Polars,自托管+LLM+盘中监控+复盘)验证了本产品形态;`strong-stock-screener` 竞价雷达、`tickflow-assist` 关键价位告警验证提醒层需求 | 立即调研 |

**架构要求(写死)**:fetchers 层做**数据源抽象**——行情快照/分时/K线 三个接口抽象化,腾讯为默认实现,TickFlow 为可选实现,`settings.yaml` 一行切换。核心引擎只依赖抽象接口,不绑死任何数据源。

**调研任务(开工前/并行)**:clone TSP 深读,输出"可借鉴点 + 数据源接入接口定义"到 `docs/调研-TSP.md`。
