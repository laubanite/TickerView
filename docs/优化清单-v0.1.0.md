## 1. 手机一键查询服务 🟢(已采纳,不着急排期)

**背景(2026-08-17 讨论)**:放弃 Windows 计划任务自动化——电脑关机 → 错过抓取;电脑常开 → 15 分钟 monitor + 早晚定时频繁抓数/LLM → 卡机。改为**按需一键查**:手机随时触发,查完即止,无任何定时任务。

**方案**:电脑常驻一个轻量 Flask 查询服务(空闲近零负载),手机浏览器主屏快捷方式点开就是按钮页:

```
AlphaPrism
[盘后简报] [盘前简报] [盘中监测] [信号/结构] [状态] [帮助]
```

每次点击 = 临时抓最新数据 + 算简报(10–30 秒),复用现有 `run_daily / morning / monitor / signals / status` 模块。

- **访问档位**:① 局域网(家里 Wi-Fi,零配置)→ ② 需要外出时再加 ZeroTier(免费 P2P;备选花生壳,国内原生但要实名+限带宽)
- **安全**:token 保护(放 `settings.local.yaml`,gitignore)
- **结果格式**:先纯文本/简单 HTML,可升级卡片
- **容错**:串行查询 + 先回"查询中" + 抓数/LLM 失败发错误摘要,不崩

**附带动作(实施时一并做)**:
- 删除 3 个计划任务(AlphaPrismMorning / AlphaPrismDaily / AlphaPrismMonitor)
- 查询服务改为开机登录自启(启动项,非定时)
- push 模块保留但不自动发;飞书配置留档

**已否决的备选**:飞书机器人方案 —— 需要企业/组织飞书建自建应用,用户当前是个人飞书,建不了(2026-08-17 确认)。

## 2. 信号关键位分层 ✅(v1 已实现 2026-08-17;待调点见下)

**问题**:支撑/压力 = 笔端点(最后一笔顶/底),单笔跨度可达近一个月(如 516020 笔 6/23→7/20,
支撑 0.778/压力 0.964,现价 0.863 居中)→ 对动作无意义;「观望(买点结构已过)」成噪音。

**实现(2026-08-17 落地,CLI/日报/全池已生效)**:
- **结构位**(笔端点,保留):大级别攻守/失效判据。单独暴露 `structure_support` / `structure_resistance`。
- **近端位**(新增,买卖点锚点;`signals/structure.py near_levels()`):
  - 均线 **MA5/10/20/60/120/250**(用户确认全周期;短 5/10/20 供回踩与盘中、中 60/120、年线 250 作牛熊参考)
  - 近 60 日前高/前低(已确认分型极值;支撑=现价下方最近底,压力=现价上方最近顶)
  - 密集成交区(近 120 日量价分布峰区,箱宽~1%;⚠️ ETF 仅近似)
  - 缺口(近 60 日)
- **信号判定**(`detect_signal` 改造):买点 = 回踩近端支撑(±2%);卖点 = 触及近端压力(±2%);
  同时触发取距离近者;结构位破位覆盖。`support/resistance` 字段 = 近端位。
- **展示**:CLI `signal` 分层输出(结构位/近端支撑/近端压力/均线/密集区/缺口 + 距现价%);
  日报「四」表 支撑/压力 列改近端位;`alphaprism signal 516020` 现显示「回踩近端支撑 0.850(8/14)」。

**待调点(用户看真实效果后定)**:
1. **信号翻转噪音**:价格在近端支撑/压力间震荡时,信号日级 买点→卖点→买点 切换,日志噪音增加。
   可加滞回(出现后需偏离 >5% 才失效)或最短持续 N 天。
2. **近端压力可能取到数月前的顶分型**(如 516020 近端压力 0.892 来自 6/3)而非最近前高;
   如需更贴近,可改为近 30~60 日滚动最高/最低点(不经分型确认)。
3. **signal_log 需重建**:信号定义变化,旧 567 条日志与新逻辑不一致,建议 `alphaprism log backfill`(结果列当前全空,清了不亏)。
4. **盘中 monitor**:已用新支撑语义,首次真实交易时段跑一轮确认。

## 3. 回测可信度修复 🟢(已采纳 2026-08-17,地基)

**问题**:回测数字不可信(胜率 57~82%、盈亏比 5~53 倍、累计收益最高 404%)——
1. **前视偏误(主)**:分型在合并 K 线第 i 根确认需比较 i±1(第 i+1 根才知道 i 是极值);
   笔的完成要等下一对立分型。`detect_signal` 按 `笔端日期 ≤ 当天` 过滤 → 用了未来 1 根以上信息。
   修法:回测每步只用 ≤idx 数据重建分型/笔,分型延迟 ≥1 根确认(缠论回测标准做法)。
2. **无成本**:ETF 双边佣金+滑点 ~0.1%,需计入。
3. **满仓单仓全进全出**:与真实打法(最多3只、留一手+加仓)不符,累计收益无现实意义。
   需按资金规则建模(可复用 #5 资金规则模型)。

## 4. signal 数据新鲜度 🔴(2026-08-17 提出)

**问题**:`alphaprism signal` 纯读库(`_load_daily` 查 SQLite),不抓新。计划任务禁用期间,
库里数据停在 8/12(实际最新应至少 8/14),用户跑 signal 看到「最新 2026-08-12」误以为接口滞后。
另:盘中 partial bar(如 8/17 10:18 抓的当日部分 bar)被当完整收盘 bar。

**方向**:
- `signal` 加 `--live`(默认先抓最新日线再算),或至少显示「数据截至 X,可跑 alphaprism daily 更新」
- 识别并覆盖盘中 partial bar(当日未收盘时标注,或 daily 后自动覆盖)
